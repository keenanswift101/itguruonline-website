<!-- Netlify Scheduled Functions v2 format — from RESEARCH.md Section 1 -->

Exact TypeScript export syntax required:
```typescript
import type { Config } from "@netlify/functions"

export default async (req: Request): Promise<void> => {
  const { next_run } = await req.json()
  // call shared job logic
  console.log("Next run at:", next_run)
}

export const config: Config = {
  schedule: "0 8 * * *"
}
```

Key facts:
- File extension MUST be .mts (per D-07 and Netlify docs)
- Return type is Promise<void> — NOT Response
- The function receives a Request object, body contains { next_run: "<ISO-8601>" }
- No Context parameter needed for scheduled functions
- @netlify/functions provides the Config type (installed in Plan 05-03 Task 1)
- @/ alias resolves in netlify/functions/ because Netlify's esbuild reads tsconfig.json paths

From src/lib/automation/ (Plan 05-02):
```typescript
// enquiry-reminder.ts
export async function runEnquiryReminderJob(opts?: { triggeredBy?: string }): Promise<{ sent: number; skipped: number }>

// invoice-reminder.ts
export async function runInvoiceReminderJob(opts?: { triggeredBy?: string }): Promise<{ sent: number; skipped: number }>

// recurring-billing.ts
export async function runRecurringBillingJob(opts?: { triggeredBy?: string }): Promise<{ inserted: number; skipped: number }>
```

Cron schedule reference (per D-07):
| Function file | Schedule | Meaning |
|---|---|---|
| enquiry-reminder.mts | "0 8 * * *" | Daily 08:00 UTC |
| invoice-overdue-reminder.mts | "0 8 * * *" | Daily 08:00 UTC |
| recurring-billing.mts | "0 7 1 * *" | 1st of each month 07:00 UTC |

Fallback if @/ alias fails at Netlify build time (Pitfall 1 from RESEARCH.md Section 9):
If the Netlify function logs show "Cannot find module '@/lib/...'" on first deploy, replace the @/ imports with relative paths using .js extension:
- `import { runEnquiryReminderJob } from "../../src/lib/automation/enquiry-reminder.js"`
(Note: .js extension is required for ESM relative imports with esbuild, even though the source is .ts)
