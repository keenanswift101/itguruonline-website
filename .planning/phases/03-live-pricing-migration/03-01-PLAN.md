<objective>
Extend the Drizzle schema with three new tables — `hosting_packages`, `domain_prices`, and `site_settings` — and generate a migration that both creates them and seeds them with the existing hardcoded pricing data. This is the foundation for the entire phase: the DB becomes the single source of truth for pricing before any code reads from it or the TS constants are deleted.

Purpose: Establishes the pricing data layer. The seed data (transcribed from `HOSTING_PACKAGES` and the two hardcoded fee/email constants) MUST live in the migration itself so the DB is populated the moment the migration runs — before the TS constants are removed in Plan 03-02. This ordering is what prevents the "HOSTING_PACKAGES is not defined" production crash (Research Pitfall 1).
Output: Extended `schema.ts` + a generated-then-seeded migration SQL file.
</objective>

```typescript
export const hostingPackages = pgTable("hosting_packages", {
  id: serial("id").primaryKey(),

  name: varchar("name", { length: 64 }).notNull(),
  priceRands: integer("price_rands").notNull(),
  pricePeriod: varchar("price_period", { length: 8 }).notNull().default("mo"),

  features: text("features").notNull().default(""), // newline-separated

  updatedAt: timestamp("updated_at", { withTimezone: true })

export const domainPrices = pgTable("domain_prices", {
  tld: varchar("tld", { length: 16 }).primaryKey(),
  priceRands: integer("price_rands"), // nullable — NULL = no price shown

  value: text("value").notNull().default(""),
  updatedAt: timestamp("updated_at", { withTimezone: true })
    .notNull().defaultNow().$onUpdate(() => new Date()),
});
```
